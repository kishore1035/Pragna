# Deploying mimir to Render

This repo is wired for Render as a single Blueprint (see `render.yaml`).
It provisions two Web Services from the same repo: a FastAPI backend and
the Next.js chatbot UI.

## What's already in place (in this commit)

- `render.yaml` — Blueprint that creates both services + a 5 GB persistent
  disk for SQLite + Chroma.
- `backend/app/config.py` — new env vars:
  - `BACKEND_PUBLIC_URL` (used to build OAuth callback URLs)
  - `FRONTEND_PUBLIC_URL` (used for CORS allow-list)
  - `CORS_ALLOW_ORIGINS` (optional, comma-separated override)
- `backend/app/main.py` — CORS now reads from settings; credentialed
  responses enabled.
- `backend/app/routes/oauth.py` — OAuth redirect URIs are env-driven, no
  longer hardcoded to `localhost`.
- Frontend reads `NEXT_PUBLIC_API_BASE` (already supported, no code change).

## What you have to do (Render side)

1. Push this branch to GitHub/GitLab. The Blueprint needs a git remote.
2. Sign in to https://dashboard.render.com → **Blueprints** → **New
   Blueprint Instance** → connect the repo.
3. Render will read `render.yaml` and create two services plus a disk. It
   will pause and ask you to fill in the values it can't generate. Enter
   them when prompted:

   On `mimir-backend`:
   | Key | What to put |
   | --- | --- |
   | `OLLAMA_URL` | Public URL of an Ollama instance. See "Ollama" below. |
   | `CHAT_MODEL` | Model name available on that Ollama (e.g. `llama3.1:8b`, `gemma4:cloud`). |
   | `EMBED_MODEL` | Embedding model (e.g. `nomic-embed-text`). |
   | `JWT_SECRET` | Already auto-generated by Render. Don't change it. |
   | `BACKEND_PUBLIC_URL` | Leave blank on first deploy, then set to `https://<service>.onrender.com` after the first deploy completes (or just let it derive from the request — it falls back to the request's own scheme/host). |
   | `FRONTEND_PUBLIC_URL` | `https://<frontend-service>.onrender.com` (from the next service). You can set it after both services exist. |
   | `CORS_ALLOW_ORIGINS` | `<frontend-url>,http://localhost:4028` (the localhost is harmless and helps local testing). |
   | `BRAVE_SEARCH_API_KEY` | Optional. Get one at https://brave.com/search/api/ |
   | `STABILITY_API_KEY` | Optional. Get one at https://platform.stability.ai/account/keys |
   | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Optional. Only if you want Google sign-in. After creating the OAuth client at https://console.cloud.google.com/apis/credentials, add `<backend-url>/api/auth/google/callback` as an authorized redirect URI. |
   | `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | Optional. Same drill on https://github.com/settings/developers with callback `<backend-url>/api/auth/github/callback`. |

   On `mimir-frontend`:
   | Key | What to put |
   | --- | --- |
   | `NEXT_PUBLIC_API_BASE_URL` | `https://<backend-service>.onrender.com` |

4. Hit **Apply**. The first build will take ~3-5 min for the backend
   (Playwright + Chromium) and ~1-2 min for the frontend.
5. After the backend deploys, go back and set `BACKEND_PUBLIC_URL` to its
   real URL, then trigger a manual redeploy (or just push an empty
   commit). The reason: the OAuth callback URL needs to match the public
   hostname before Google/GitHub will accept logins.

## Ollama (the catch)

This app expects an external Ollama — Render has no free GPU tier, and
bundling Ollama into the same container would be huge and slow. Pick one:

- **Ollama Cloud** (easiest): sign up at https://ollama.com/cloud, create
  an API key, set `OLLAMA_URL=https://api.ollama.com` (or whatever the
  docs say — they changed it recently) and an `OLLAMA_API_KEY` env var.
  You'll likely need a small code change in `backend/app/ollama_client.py`
  to send the API key in the header; check what that file does today
  before deploying.
- **Self-host**: run Ollama on a paid Render background service, a
  Hetzner/AWS box, or your own machine with a tunnel. Point `OLLAMA_URL`
  at it. The model has to be reachable from the public internet, so
  firewall that down.
- **Switch providers**: replace `ollama_client.py` with an OpenAI or
  Anthropic client. This is a code change, not a config change.

## Persistent data

The 5 GB Render Disk is mounted at `/data` on the backend. `DB_PATH`,
`CHROMA_PATH`, and `DOCUMENTS_DIR` all point under `/data` so the SQLite
DB, Chroma vector store, and uploaded documents survive redeploys.

If the disk fills up, increase its size in the dashboard — Render will
resize live on the next deploy.

## Plan requirements

- Both services are on `starter` ($7/mo each as of 2026). Free tier
  will not work — the backend build alone takes 2-3 min (Playwright +
  Chromium) and free instances idle-out and lose in-memory cron state.
- A `Starter` web service has 512 MB RAM. That's fine for FastAPI + a
  small Chroma index, but if you upload a lot of documents you'll want
  `Standard` (2 GB) or larger.

## After the first deploy

- Test: open the frontend URL, register an account, send a message. The
  first chat will be slow because Ollama has to load the model.
- Check the backend logs: `https://dashboard.render.com/.../logs`. If you
  see `Could not connect to Ollama at <url>`, fix `OLLAMA_URL`.
- If login fails with a CORS error in the browser console, the
  `FRONTEND_PUBLIC_URL` on the backend doesn't match the URL you opened.
  Add it to `CORS_ALLOW_ORIGINS` and redeploy.

## Local dev

The new env vars are all optional. With no changes, `backend/.env`
keeps the localhost defaults and the OAuth callback is `localhost:8000`,
which is what you want for local testing.
